## 1. Supabase LockManager API 에러

### 문제 상황
```
AbortError: signal is aborted without reason
at eval (locks.js:108:29)
```

React Strict Mode에서 `useEffect`가 두 번 실행되면서 Supabase의 LockManager API에서 발생하는 에러. 여러 탭이나 컴포넌트가 동시에 lock을 획득하려고 시도하면서 발생.

### 증상
- 브라우저 콘솔에 `AbortError` 에러 발생
- User 정보를 제대로 불러오지 못함
- 로그아웃이 정상 작동하지 않음
- 기능은 작동하지만 QA 파이프라인에서 문제 발생

### 해결 방법

#### 1) `mat_we/lib/client.ts` - 커스텀 Lock 함수 추가

```typescript
import { createBrowserClient } from "@supabase/ssr"

// LockManager API 에러 방지를 위한 no-op lock 함수
// GitHub issue: https://github.com/supabase/supabase-js/issues/1517
const noOpLock = async <T>(
  _name: string,
  _acquireTimeout: number,
  fn: () => Promise<T>
): Promise<T> => {
  return await fn()
}

export function createClient() {
  return createBrowserClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      auth: {
        lock: noOpLock,
        persistSession: true,
        autoRefreshToken: true,
      },
    }
  )
}
```

#### 2) `mat_we/hooks/use-user.ts` - 컴포넌트 Cleanup 처리

```typescript
useEffect(() => {
  const supabase = createClient()
  let isMounted = true
  const abortController = new AbortController()

  const getInitialUser = async () => {
    // ... 기존 로직

    // 모든 setState 전에 isMounted 체크
    if (!isMounted) return

    // AbortError 핸들링
    if (error instanceof Error && error.name === "AbortError") {
      console.log("[useUser] Request aborted (component unmounted)")
      return
    }
  }

  return () => {
    isMounted = false
    abortController.abort()
    subscription.unsubscribe()
  }
}, [initialUser, initialProfile])
```

### 참고 자료
- [Supabase Issue #1517: NavigatorLockAcquireTimeoutError](https://github.com/supabase/supabase-js/issues/1517)
- [Supabase Issue #1594: GoTrueClient uses infinite timeouts](https://github.com/supabase/supabase-js/issues/1594)

## 2. SSR Authentication State Hydration 문제

### 문제 상황
- 서버에서 사용자 인증 정보를 정상적으로 가져옴
- 클라이언트에서 HeaderClient 컴포넌트가 `undefined` 표시
- 초기 렌더링 시 깜빡임 현상 발생 (flash of unauthenticated UI)
- 로그에는 사용자 이메일이 표시되지만 UI에는 반영되지 않음

### 원인 분석
1. **Middleware가 정상 작동**: `updateSession` 함수가 쿠키를 통해 인증 상태를 올바르게 관리
2. **Server Component가 데이터를 가져옴**: Header 컴포넌트가 `initialUser`와 `initialProfile`을 정상 fetch
3. **Client Component가 props를 무시**: HeaderClient가 서버에서 전달받은 props를 사용하지 않고 client-side hook만 사용
4. **Hydration Mismatch**: 서버는 user 데이터로 렌더링하지만, 클라이언트는 항상 null/undefined로 시작

### 해결 방법

#### 1) `mat_we/components/layout/header-client.tsx` - Props 인터페이스 추가

```typescript
import type { User as SupabaseUser } from "@supabase/supabase-js"
import type { Profile } from "@/lib/database"

interface HeaderClientProps {
  initialUser?: SupabaseUser | null
  initialProfile?: Profile | null
}

export default function HeaderClient({
  initialUser,
  initialProfile
}: HeaderClientProps) {
  const { user, profile, isLoading } = useUser(initialUser, initialProfile)
  // ...
}
```

#### 2) `mat_we/hooks/use-user.ts` - SSR 초기값 지원

```typescript
export function useUser(
  initialUser: User | null = null,
  initialProfile: Profile | null = null
) {
  const [user, setUser] = useState<User | null>(initialUser)
  const [profile, setProfile] = useState<Profile | null>(initialProfile)
  const [isLoading, setIsLoading] = useState(false)

  useEffect(() => {
    const getInitialUser = async () => {
      if (initialUser !== null) {
        // SSR에서 이미 데이터를 받았으면 스킵
        console.log("[useUser] Using SSR initial data:", initialUser?.email)
        return
      }
      // 초기값이 없을 때만 client-side fetching
      // ...
    }
  }, [initialUser, initialProfile])
}
```

### 결과
- Hydration mismatch 해결
- 초기 로딩 깜빡임 제거
- 서버와 클라이언트 상태 동기화
- 불필요한 클라이언트 API 호출 제거

## 3. Google OAuth PKCE Code Verifier 에러

### 문제 상황
```
PKCE code verifier not found
```

Google OAuth 로그인 시 PKCE (Proof Key for Code Exchange) 검증 실패.

### 원인
`mat_we/lib/client.ts`의 browser client가 **localStorage**를 사용하도록 설정되어 있었지만, Supabase SSR에서는 **cookie 기반 저장소**를 사용해야 함.

### 해결 방법

#### `mat_we/lib/client.ts` - Cookie 기반 저장소 사용

**변경 전:**
```typescript
export function createClient() {
  return createBrowserClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!
  )
}
```

**변경 후:**
```typescript
export function createClient() {
  return createBrowserClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      auth: {
        lock: noOpLock,
        persistSession: true,
        autoRefreshToken: true,
      },
    }
  )
}
```

> **참고**: `@supabase/ssr`의 `createBrowserClient`는 기본적으로 cookie 기반 저장소를 사용합니다.

### Middleware 설정
`mat_we/lib/proxy.ts`의 `updateSession` 함수가 SSR 클라이언트를 생성하고 쿠키를 올바르게 관리:

```typescript
export async function updateSession(request: NextRequest) {
  const supabase = await createClient()
  const { data: { user } } = await supabase.auth.getUser()
  // 쿠키 동기화 및 라우트 보호 로직
}
```

## 4. React Hook Form 통합 및 무한 로딩 이슈

### 문제 상황
1. `create-post-form.tsx`에서 글 작성 시 무한 로딩
2. 네트워크 요청이 트리거되지 않음
3. Form 제출 후 응답이 없음

### 해결 과정

#### 1단계: React Hook Form 통합 (`#2711`, `#2712`)

**변경 사항:**
- `react-hook-form`과 `zod`를 사용한 폼 검증
- Field-level validation 추가
- 타입 안정성 향상

```typescript
import { useForm } from "react-hook-form"
import { zodResolver } from "@hookform/resolvers/zod"
import * as z from "zod"

const postSchema = z.object({
  title: z.string().min(1, "제목을 입력해주세요"),
  content: z.string().min(1, "내용을 입력해주세요"),
  // ...
})

export default function CreatePostForm() {
  const form = useForm({
    resolver: zodResolver(postSchema),
    defaultValues: { /* ... */ }
  })

  const onSubmit = async (data: z.infer<typeof postSchema>) => {
    // 제출 로직
  }
}
```

#### 2단계: 네트워크 요청 디버깅 (`#2713`, `#2714`)

**문제**: 글 작성 시 Supabase API 호출이 발생하지 않음

**디버깅 추가:**
```typescript
console.log("[CreatePostForm] Submitting data:", data)
const { data: result, error } = await supabase
  .from("community_posts")
  .insert(insertData)
console.log("[CreatePostForm] Insert result:", result, error)
```

#### 3단계: Rich Editor 이벤트 플로우 분석 (`#2715`)

TipTap Editor와 React Hook Form 간의 통합 확인:
- Editor의 onChange 이벤트가 form state를 올바르게 업데이트하는지 검증
- 한글 입력 테스트 통과 (`#2717`)

#### 4단계: Supabase 환경 변수 확인 (`#2722`, `#2723`, `#2724`)

`.env.local` 파일의 환경 변수가 올바르게 설정되어 있는지 확인:
```bash
NEXT_PUBLIC_SUPABASE_URL=your-project-url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
```

### 최종 해결
- React Hook Form 통합 완료
- Field-level validation 작동
- Supabase insert 성공
- 한글 입력 정상 작동

#### 현재 안정 버전 (`package.json`)

```json
{
  "dependencies": {
    "react": "18.3.1",
```

- `"use client"` 지시어 적절히 사용

#### 2) React 18 Features
- Concurrent Rendering 지원
- Automatic Batching
- Transitions API
- Suspense 개선

#### 3) TypeScript 설정
```json
{
  "compilerOptions": {
    "target": "ES2017",
    "lib": ["dom", "dom.iterable", "esnext"],
    "jsx": "preserve",
    "moduleResolution": "bundler"
  }
}
```

### 버전 변경 시 주의사항

1. **의존성 재설치**


3. **타입 에러 확인**

## 6. 랜딩페이지 애니메이션 이중 실행 (Provider 조건부 렌더링)

### 문제 상황
- 랜딩페이지의 `FadeInSection` 애니메이션이 새로고침 시 깜빡이면서 두 번 실행됨
- 페이지 간 클라이언트 네비게이션에서는 정상 작동
- `FloatingChatProvider`를 `layout.tsx`에 추가한 이후 발생

### 원인 분석

`FloatingChatProvider`에서 로그인 여부에 따라 **컴포넌트 트리 구조 자체를 변경**하고 있었음:

```tsx
// floating-chat-provider.tsx (변경 전)
export function FloatingChatProvider({ children }) {
  const { data: profile } = useCurrentProfile();

  // 비로그인 → Fragment로 감싸서 반환
  if (!profile) {
    return <>{children}</>;
  }

  // 로그인 → Provider로 감싸서 반환
  return (
    <FloatingChatContext.Provider value={...}>
      {children}
      <FloatingChatButton />
      <ChatPanel />
    </FloatingChatContext.Provider>
  );
}
```

**실행 흐름 (새로고침 시):**
1. 초기 렌더링: `useCurrentProfile()` 로딩 중 → `profile = undefined` → `<Fragment>{children}</Fragment>`
2. `FadeInSection` 마운트 → IntersectionObserver 감지 → 애니메이션 1회 실행
3. 프로필 로드 완료 → `profile` 존재 → `<Provider>{children}</Provider>`로 트리 구조 변경
4. React가 트리 구조 변경 감지 → children 전체 **언마운트 후 재마운트**
5. `FadeInSection` 상태 초기화 (`isVisible: false`) → 애니메이션 2회째 실행

**핵심**: React는 부모 컴포넌트 타입이 `Fragment` → `Provider`로 바뀌면 children을 재사용하지 않고 완전히 새로 마운트함.

### 해결 방법

항상 동일한 트리 구조(Provider)를 유지하고, 채팅 UI만 조건부 렌더링:

```tsx
// floating-chat-provider.tsx (변경 후)
export function FloatingChatProvider({ children }) {
  const { data: profile } = useCurrentProfile();

  return (
    <FloatingChatContext.Provider value={...}>
      {children}
      {profile && <FloatingChatButton />}
      {profile && <ChatPanel />}
    </FloatingChatContext.Provider>
  );
}
```

### 결과
- 프로필 로딩 상태와 관계없이 항상 `Provider > children` 구조 유지
- children이 재마운트되지 않으므로 애니메이션 상태 보존
- 채팅 버튼/패널은 로그인 시에만 표시 (기존 동작 유지)

### 교훈
- **Provider 컴포넌트에서 조건부로 다른 wrapper를 반환하면 안 됨** — children 전체가 재마운트됨
- 조건부 렌더링은 항상 트리 구조를 유지한 채로, 내부 요소만 on/off 해야 함
- 특히 `layout.tsx`처럼 전체 앱을 감싸는 Provider에서 이 실수를 하면 모든 페이지에 영향
